~/.ssh/config is for your user — SSH client behavior
/etc/ssh/ssh_config is system-wide — same syntax, lower priority
Don't confuse with /etc/ssh/sshd_config — that's the server config
Simple example of ~/.ssh/config:
Host myserver
    HostName 192.168.1.50
    User dev
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
Now instead of: 	ssh -p 2222 -i ~/.ssh/id_ed25519 dev@192.168.1.50
You just run:		ssh myserver


.ssh is where SSH looks for:
~/.ssh/id_ed25519 / id_rsa — private keys
~/.ssh/id_ed25519.pub — public keys
~/.ssh/authorized_keys — keys allowed to log in
~/.ssh/known_hosts — fingerprints of servers you've connected to
~/.ssh/config — client config




mkdir -p /run/sshd
/usr/sbin/sshd
================
Line 1: mkdir -p /run/sshd
Why does sshd need this?
sshd uses /run/sshd as its runtime directory — a place to store things like:
The privilege separation directory (UsePrivilegeSeparation sandbox)
Unix socket / lock files needed while running
/run is a tmpfs — it lives in RAM and is wiped on every boot (and in containers, it starts empty). So even though the directory may have existed in the image, it's gone at container start and must be recreated before sshd launches.

Line 2: /usr/sbin/sshd
Runs the SSH daemon (server).
What it does
Reads /etc/ssh/sshd_config
Binds to port 22 (or whatever Port says)
Listens for incoming SSH connections


sshd and the ssh client refuse to use files that are group/world-writable or not owned by the right user. They do this because a world-writable key file would let any other user on the box swap your key for theirs and impersonate you.
The rules, roughly:
~/.ssh (the directory): must be 700 — only the owner can enter/modify it. If someone else can write here, they can replace authorized_keys or id_ed25519.
Private keys (id_ed25519): must be 600 — owner read/write only. If anyone else can read it, it's compromised.
authorized_keys: must be 600 (or 644 in some setups) — writable only by the owner, since whoever can write it can add their own key.
config: must not be group/world-writable — 600 is safest.
Ownership: all of the above must be owned by the user logging in — dev, not root.










useradd -m -s /bin/bash dev
passwd dev                      # set password (optional in containers)
-m → create home directory (/home/dev)
-s /bin/bash → set login shell (default is often /bin/sh)
Without -m, no home dir is created — a common gotcha.

Add a user to a group
bash
sudo usermod -aG sudo dev       # add dev to sudo group
sudo usermod -aG docker dev     # add dev to docker group
-a = append (never omit it — without -a, the user is removed from all other groups!)
-G = supplementary groups list


Edit sudoers safely:
sudo visudo                      # main file
sudo visudo -f /etc/sudoers.d/dev   # drop-in file (preferred)

Examples:
dev   ALL=(ALL) NOPASSWD:ALL               # full passwordless sudo
%devs ALL=(ALL) /usr/bin/apt-get           # group "devs" may only run apt-get
dev   ALL=(ALL) /bin/systemctl restart nginx
